# Wujie / Jieshu 对比测试计划

制定时间：2026-09-09。目标是检验启动速度、内存开销和稳定性，不预设胜者。

## 基线和公平性

- 测试当前两个本地仓库的已提交源码，保存完整 commit、工作区状态与包版本。
- 使用同一个 Vite 版本将两份 core 源码分别构建为生产压缩 IIFE，目标 ES2018；记录原始及 gzip 体积。避免沿用可能过期的 dist。
- 统一主页面、子应用 HTML/JS/CSS、DOM 负载、生命周期和通信；子应用仅在框架接入的全局变量名上兼容两者。
- 主子应用在不同本地 HTTP 端口，资源允许 CORS；单浏览器、单 worker，交错测试顺序，不同时运行其他测试。
- 新 context 表示冷的浏览器/框架缓存，不代表冷 OS 文件缓存或真实公网。固定浏览器版本、视口及启动参数。
- 区分 API Promise 返回与页面 ready；主要启动指标是调用 start 到子应用完成渲染后的帧边界，同时报告 Promise 返回时间。

## 测试矩阵

1. 启动：冷启动、销毁后缓存重建、保活应用切回、预加载后进入、多应用并发启动；补充资源延迟及 CPU 降速条件。每框架每场景至少 30 个独立样本，预热不纳入统计，报告 N、失败数、中位数、P95、bootstrap 中位数差异区间。
2. 内存：加载核心前、加载后、一个/多个应用挂载后、重复创建销毁 30 次的阶段快照；至少 5 轮。Chromium CDP 强制 GC 后采集 JSHeapUsedSize、Nodes、Documents、JSEventListeners，记录整个序列。它们不是浏览器总内存，也不能单独证明泄漏。
3. 稳定性：基础渲染和点击、props、事件总线、JS/CSS 隔离、多应用共存、销毁重建、保活、路由同步、异步卸载、并发操作、预加载、动态资源和资源失败恢复。每项至少 3 轮，相同输入和断言，不以重试覆盖失败。
4. 既有回归：在对比采样之外执行 Jieshu 核心单元测试和浏览器回归，记录命令及结果；它们作为补充证据，不与不同覆盖面的 Wujie 测试直接计算胜负。

## 输出和问题记录

- 脚本放在 `benchmarks/comparison/`，原始观测和环境信息保留在 `results/`，大体积临时浏览器产物保存在忽略的 `test-results/`。
- 报告包含样本、分布、相对差异、异常及适用边界；问题按复现步骤、预期、实际、频率、影响和状态记录。
- 失败时先排除夹具错误、缓存/构建差异和 API 接入差异；框架缺陷和文档规定的能力差异分别表述。
- 本轮只新增测试与记录，不修改被测核心、适配包、发布配置，不创建提交。
- Chromium 合成 core 负载的结果不能推广为全部业务、全部浏览器、移动端、适配包或长期运行稳定性；未覆盖部分明确保留为后续矩阵。

## 已发现的准备阶段问题

- ENV-001：AGENTS.md 写 pnpm 11.13.0，实际根 package.json 指定 pnpm 10.28.2，PATH 中命令为 11.19.0。以 packageManager 为准；复用已安装依赖，通过 node 执行本地测试 CLI，不安装或改写依赖。

## 执行完成记录

- 本计划已执行：启动 9 场景 × 30 样本 × 2 框架，内存 5 轮 × 2 框架，稳定性 16 场景 × 3 轮 × 2 框架；共 646 条正式观测。
- 根据预检增加 5.5 秒静置后的内存采样，避免把 Wujie 的短期引用保留误报为永久泄漏；五应用内存阶段之前也先静置，避免混入循环残留。
- 预检审查后将实际可见 DOM 检查纳入计时；并发场景允许明确 AbortError，另检查旧 Loading 的清理。正式测试统一使用这些断言。
- 补充执行 Jieshu 478 项单测、130 项核心 Chromium 回归，以及 Wujie 94 项单测；均通过。对比稳定性自身有 12 条失败，完整记录，没有修改被测核心使结果通过。
