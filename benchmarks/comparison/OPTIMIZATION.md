# Jieshu 性能优化计划与执行记录

日期：2026-09-09。承接[首次对比](./REPORT.md)，用户已授权修改 Jieshu 核心，目标是消除相对本地 Wujie 的退化。原始基线目录保持不变，不修改 Wujie 来改变对照结果。

## 执行顺序

1. 从首次原始数据筛出差距：五应用并发启动、CPU 降速、fiber 长尾、挂载内存、核心体积及空载内存；同时修复并发取消残留 Loading。
2. 用启动 CPU profile 和销毁后堆快照定位成本，区分每应用重复分配、等待调度、必要功能代码和失效引用。
3. 先保留行为回归，再减少重复工作：按需读取子窗口 DOM 构造器、共享元素描述符与 WeakRef、减少空数组和冗余函数缓存、删除 fiber 的空异步等待、按归属释放 Loading。
4. 独立审查跨 realm、销毁回退、异步脚本完成、微任务取消和嵌套容器等边界；执行核心单元、浏览器、类型和真实示例集成测试。
5. 停止其他重负载测试，按原矩阵重新进行完整采样；同时重测未改动的 Wujie，不把不同时间的绝对耗时直接当作优化收益。每次运行保留独立目录和 bundle 哈希。
6. 更新问题状态并记录结果、剩余差距与下一步。有限场景的中位数接近不能证明所有场景等价；较大的包和空载内存仍须明示。

## 诊断与阶段采样

以下目录是忽略的本地诊断产物，不能替代正式完整结果。单轮内存和较少启动样本只用于确定方向。

| ---------------------------------------- | ------------------------------------------------------------------------------------------- |

| `test-results/comparison-opt-pass1`      | 首次热点优化后，4 个场景每框架 15 个样本                                                    |
